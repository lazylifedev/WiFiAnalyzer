# Phase 7A-2 kintone 手動確認

## 事前準備

1. kintone アプリへ Wi-Fiアナライザー連携プラグインを追加する。
2. フォームフィールド取得とレコード閲覧だけを許可した API トークンを発行する。
3. プラグインで専用 QR コードを生成する。
4. Android アプリを確認済みの Pro 状態にする。

## Android での確認

1. 設定 → データ → kintone連携を開く。
2. 「QRコードを読み取る」を押し、カメラ権限を許可する。
3. QR を枠内に合わせる。
4. HTTPS 接続確認後、ドメイン、アプリID、各仕様バージョン、ワークスペース、警告を確認する。
5. APIトークン本文が表示されず「設定済み」とだけ表示されることを確認する。
6. 「この内容で接続」を押し、接続済み表示になることを確認する。
7. 「接続を確認」で再検証できることを確認する。
8. 「QRコードを再読取」で、保存完了までは既存接続が維持されることを確認する。
9. 「連携を解除」で説明を確認し、解除する。
10. アプリの cold start 後も接続状態が正しく復元されることを確認する。

## 実環境でのみ確認できる項目

- 実プラグインが生成する QR JSON と想定キーの一致。
- fieldSchemaVersion=1 は、写真以外の15フィールドを接続必須、写真（FILE）を警告付き任意として検証する。
- REST API の型名 `MULTI_LINE_TEXT` と `CHECK_BOX` を使用し、テンプレート内部型名は検証に使用しない。
- 機器UUIDは `SINGLE_LINE_TEXT`、required=true、unique=true、maxLength 36以上を確認する。APIでuniqueを取得できない場合は確認済み扱いにせず警告する。
- 削除状態は `CHECK_BOX` かつ「削除済」を完全一致で必須とする。アプリ更新日時の現在日時初期値と未知フィールドは警告扱いとする。
- kintone の 401 / 403 / 404 / 429 / 5xx 応答と権限構成。
- TLS、DNS、タイムアウト、別ホストリダイレクト拒否。

リポジトリには実プラグインソースとテンプレート定義が含まれていないため、フィールドコードを推測していない。現状はフォームレスポンス形式とレコード閲覧権限を検証し、フィールドの完全照合は警告として表示する。
